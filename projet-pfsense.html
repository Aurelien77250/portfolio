Mise en place d'un pare-feu PfSense

PfSense Firewall Réseau Active Directory DHCP Relay
Contexte du projet

Objectif — Installer et configurer un pare-feu PfSense dans une architecture réseau existante : paramétrer les interfaces WAN et LAN, créer des règles de filtrage avancées (trafic Web, DNS, jonction de domaine, accès horaire), et activer un relay DHCP pour les postes clients.

Plan d'adressage — Architecture réseau

Avant toute configuration, définition du plan d'adressage de l'ensemble des équipements de l'infrastructure :

Équipement Interface Adresse IP Masque Passerelle
Firewall PfSense eth0 — WAN 192.168.240.20 /24 FAI
eth1 — LAN SVR 192.168.2.30 /27 FAI
eth2 — LAN PDT 192.168.1.254 /24 FAI
DC1 (Serveur AD) NIC 192.168.2.2 /27 192.168.2.30
PDT (Postes clients) NIC DHCP (192.168.1.0) /24 192.168.1.254
Procédure Technique

La mise en place du PfSense s'est déroulée en 5 étapes successives, de la configuration des interfaces jusqu'à la validation des règles de filtrage.

Étape 1
Configuration des interfaces WAN et LAN
Assignation des interfaces réseau du pare-feu via la console PfSense et l'interface web.
  • Connexion à la console PfSense et assignation des interfaces (em0 → WAN, em1 → LANSUR, em2 → LANPDT).
  • Configuration des adresses IP via l'option 2 du menu console.
  • WAN : 192.168.240.20 /24
  • LAN SVR : 192.168.2.30 /27
  • LAN PDT : 192.168.1.254 /24
  • Vérification des interfaces depuis l'interface graphique web PfSense.

Étape 2
Règle de filtrage — Trafic Web (HTTP/HTTPS)
Création d'un alias regroupant les ports 80 et 443, puis configuration de la règle permettant la navigation web depuis le LAN PDT.
Création de l'alias "AccesWEB"
  • Aller dans Firewall → Aliases → Ports.
  • Créer un alias de type Port(s) nommé AccesWEB.
  • Ajouter les ports 80 (HTTP) et 443 (HTTPS).
Création de la règle firewall
  • Action : Pass — Interface : LANPDT — Protocole : TCP/UDP
  • Source : LANPDT subnets — Destination : Any
  • Port destination : alias AccesWEB (80, 443).

Étape 3
Règles DNS — Alias "DNSlocal"
Création d'un alias IP pointant vers le contrôleur de domaine DC1, puis règle autorisant les requêtes DNS depuis les deux LAN.
Création de l'alias "DNSlocal"
  • Aller dans Firewall → Aliases → IP.
  • Créer un alias de type Host(s) nommé DNSlocal avec l'IP 192.168.2.2 (DC1).
Règle DNS sur chaque interface LAN
  • Action : Pass — Protocole : UDP — Port : 53 (DNS)
  • Source : LANPDT subnets — Destination : alias DNSlocal.
  • La même règle est créée sur l'interface LANSUR.
  • Test de validation via nslookup depuis un poste client → réponse sur 192.168.2.2.
Capture : Alias DNSlocal — IP 192.168.2.2
Capture : Test nslookup — serveur DNS résolu sur 192.168.2.2
Étape 4
Règle jonction de domaine + Relay DHCP
Ouverture des ports nécessaires à l'intégration d'un poste au domaine Active Directory, et activation du relay DHCP pour transmettre les requêtes au serveur DC1.
Alias "AjoutDomaine" — Ports AD
  • Créer un alias de type Port(s) nommé AjoutDomaine.
  • Ports inclus : 135, 389, 636, 3268, 3269, 53, 88, 445, 1024:65535.
Règle jonction domaine
  • Action : Pass — Interface : LANPDT — Protocole : TCP/UDP
  • Source : LANPDT subnets — Destination : LANSUR subnets
  • Port destination : alias AjoutDomaine.
Activation du relay DHCP
  • Aller dans Services → DHCP Relay → activer la case Enable DHCP Relay.
  • Sélectionner les interfaces WAN, LANSUR, LANPDT.
  • Renseigner le serveur upstream : 192.168.2.2 (DC1).
  • La plage DHCP sur le serveur AD couvre 192.168.1.1 → 192.168.1.254.

Étape 5
Règle horaire — Accès au serveur Web interne (8h–18h)
Mise en place d'une plage horaire sur PfSense limitant l'accès au serveur Web interne (IIS sur DC1) aux heures ouvrées uniquement.
Installation du service IIS
  • Sur DC1, installer le rôle IIS (Internet Information Services) via le Gestionnaire de serveur.
  • Vérifier l'accès local via http://localhost → page de bienvenue IIS affichée.
Création de la plage horaire "Acces_site_web"
  • Aller dans Firewall → Schedules → ajouter une nouvelle plage.
  • Nom : Acces_site_web — jours : Lundi–Vendredi.
  • Horaire : 08:00 → 18:00.
Règle d'accès horaire (Pass 8h–18h)
  • Action : Pass — Interface : LANPDT — Protocole : TCP
  • Destination : alias Serveur_web (IP du DC1).
  • Schedule : Acces_site_web (actif uniquement 8h–18h).
Règle de blocage (hors horaires)
  • Créer une 2ème règle identique avec Action : Block, sans plage horaire.
  • Cette règle bloque tout accès au serveur web en dehors des heures ouvrées.
  • Ordre : règle Pass (horaire) en premier, règle Block ensuite — PfSense applique les règles dans l'ordre.

Récapitulatif des règles de filtrage

Ordre final des règles configurées sur l'interface LANPDT :

Action Protocole Source Destination Port Schedule
Pass IPv4 TCP LANPDT subnets Serveur_web AccesWEB Acces_site_web
Block IPv4 TCP LANPDT subnets Serveur_web * —
Pass IPv4 TCP/UDP LANPDT subnets * AccesWEB —
Pass IPv4 TCP/UDP LANPDT subnets LANSUR subnets AjoutDomaine —
Pass IPv4 UDP LANPDT subnets DNSlocal 53 (DNS) —
